# Tips Library

Browsing YouTube Shorts tips with tag filtering. The tips library (`/tips/`) shows video cards in a grid layout, each linking to a dedicated tip page with embedded YouTube video, description, and metadata. Tips can be filtered by tags like "agentic-coding", "ai", "public-speaking", etc.

## Sub-features

- Grid of tip cards showing thumbnail, title, duration, and tags
- Tag navigation bar to filter tips by topic
- Each tip links to `/tips/<slug>/` dedicated page
- Tip page embeds YouTube Short video with play button facade (lazy-loaded)
- Tip page shows title, description, metadata (date, duration), transcript (if available), and tags
- Back links to tips index and homepage
- Tips are NOT mixed with regular articles (separate URL namespace and collections)
- Tip poster frames hosted locally for LCP performance (not YouTube thumbnails)

## How to get to it (user POV)

**From homepage**: Click "Tips" in hero navigation

**From any page**: Navigate to `/tips/` directly

**Direct URL**: `/tips/` (index), `/tips/<slug>/` (individual tip)

**From article pages**: No direct cross-linking between articles and tips (separate content types)

## Driving it with curl + grep

**Preconditions**:
- Dev server running on port 3000
- Tips data exists in `src/_data/tips.json` (generated by `scripts/fetch-youtube-shorts.mjs`)
- At least one tip published

```bash

STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$TIPS_URL")

```

## Gotchas

**Tips are NOT articles**: Tips live in a separate URL namespace (`/tips/`) and use a different data source (`src/_data/tips.json` and `src/_data/tipsLibrary.js`). They are NOT part of the `collections.catatan` collection and don't mix with blog articles.

**Tip data is generated**: The `tips.json` file is created by running `node --env-file=.env scripts/fetch-youtube-shorts.mjs`. This is a manual step, not part of `pnpm start` or `pnpm run build`. If tips.json is empty or missing, the tips pages won't render (or will render empty).

**YouTube API key required for sync**: The fetch script needs `YOUTUBE_API_KEY` environment variable to sync new tips from the YouTube channel. Without it, you can only work with existing tips in the committed `tips.json`.

**Tip poster frames are local**: The big thumbnail images behind the play button are served from `assets/images/tips/<videoId>.webp` (not YouTube's CDN). These are generated by `node scripts/fetch-tip-thumbnails.mjs` and improve LCP performance. If a tip's poster frame is missing, it falls back to YouTube's thumbnail URL.

**Poster frame manifest**: Dimensions for local poster frames are recorded in `src/_data/tipPosters.json`. This is needed because not every YouTube video has a maxres thumbnail, so the script records actual dimensions. The test `test/tip-posters.test.js` catches missing entries.

**Tag URLs**: Tip tags use `/tips/topik/<tag>/` (not `/tags/<tag>/`). This keeps tip tags separate from article tags. A tag like "ai" can exist in both namespaces with different content.

**Tip tags don't feed /tags**: The main `/tags/` page and `/tags/<tag>/` article listing pages do NOT include tips. Tips are intentionally siloed. This is documented in `AGENTS.md`.

**Lazy YouTube embed**: Tip pages use a play button facade to avoid loading YouTube's iframe until the user clicks. This saves ~2MB of JS and improves LCP. The facade is implemented in tip page template markup and CSS.

**No pagination**: The tips index shows all tips in one grid. If the channel grows to hundreds of tips, this could become a performance issue, but currently all tips fit on one page.

**Tip slugs are editable**: The slug is stored in `tips.json` and can be hand-edited (more readable than YouTube video IDs). The fetch script preserves hand-edits on re-run.

**Duration alone doesn't identify Shorts**: YouTube changed the Short duration limit from 60s to 3 minutes. The fetch script does a HEAD request to `youtube.com/shorts/<videoId>` to confirm each video is actually a Short. These confirmations are cached in `.cache/youtube-shorts/`.

**Card thumbnail vs OG thumbnail**: The tips grid uses a derived `cardThumbnail` field (from `src/libs/tips.js`) which is smaller/optimized. The tip page OG image uses the full `thumbnail` field. Don't point the grid at the full-size thumbnail.

**Transcript field**: Tips can have a `transcript` field in the JSON for accessibility and SEO. This is manually added (not auto-generated) and optional.

**Tips library template**: Uses `src/tips.njk` which imports `src/_includes/tips_grid.njk` for the card rendering macro. Individual tip pages use `src/tip.njk` template.

**Search integration**: Tips index has `data-pagefind-body`, so tips can appear in site search results. But tip tags do NOT feed the main `/tags/` or `/topik/` pages.

**Design system**: Tips cards use a different visual style than article cards - more compact, with prominent thumbnail and play button icon. This follows the "Neo-Acid Gallery" brutalist design (see `DESIGN.md`).
